# 青竹峰大衍智能问数项目完善与面试学习方案

这份方案把当前青竹峰大衍智能问数项目和本地的《RAG Agent 项目面试与知识点手册》放在一起学习。两份材料不是同一个业务项目，面试手册讲的是小说知识库 Agent，当前项目讲的是自然语言问数。它们共享 RAG、Embedding、向量库、FastAPI、LangGraph、工具调用和测试方法，数据库与业务问题不同的地方要按当前项目回答。

## 一、先把项目讲成一个面试项目

六十秒介绍可以这样说。

我做了一个自然语言问数 Agent。用户只需要输入业务问题，系统先从问题里提取指标、维度、筛选值和时间范围，再从 MySQL 元数据库读取表、字段和指标定义，用 Elasticsearch 做业务值全文召回，用 Qdrant 做字段和指标向量召回。LangGraph 把关键词提取、召回、上下文合并、SQL 生成、SQL 校验、SQL 校正和执行串成一条工作流。FastAPI 通过 SSE 返回处理阶段和最终结果。大模型使用 DeepSeek，向量模型使用 Qwen text-embedding-v3，向量维度是 1024。项目的重点是让模型根据真实元数据生成 SQL，并通过校验和重试降低猜字段和错口径的风险。

## 二、项目当前完成情况

已经完成的部分包括 Python 3.12 虚拟环境、依赖安装、FastAPI 后端、Vue 前端、DeepSeek 调用、Qwen Embedding、Qdrant 集合、Elasticsearch 索引、课程 MySQL 表结构和示例数据，以及元数据知识库构建。

已经验证的真实问题是“查询华东地区销售额最高的商品”，系统能完成关键词提取、字段和指标召回、上下文合并、SQL 生成、SQL 执行，并返回 Galaxy S24 Ultra 和 28497.0。

当前项目的两个工程改进点已经加入代码。Embedding 客户端优先读取 `ALIYUN_API_KEY`，并把 Qwen 批量请求切成每批十条。课程代码中错误的 `Lib` 导入也已经修复。

## 三、第一阶段，先能讲清楚调用链

学习目标是不用看代码，也能说清楚一次请求怎么走。

用户问题进入 `POST /api/query`。FastAPI 校验请求体。服务调用 LangGraph 图。图先提取关键词，再分别召回值、字段和指标。召回结果合并后，模型生成 SQL。校验节点检查 SQL。错误时进入校正节点。通过后访问 `dw`。结果用 SSE 发给前端。

对应面试题包括什么是 Agent、LangGraph 解决什么问题、FastAPI 为什么适合 AI 服务、SSE 为什么适合长耗时请求、trace_id 和日志有什么用。

学习动作是打开 `app/agent/graph.py`，画出节点和边。然后打开 `app/api/routers/query_router.py`，找到接口如何进入服务层。最后用浏览器前端提问一次，把每个返回阶段和代码节点对应起来。

验收标准是你能回答三个问题。输入是什么，哪一步改变了状态，输出是什么。

## 四、第二阶段，学会 RAG 和元数据

当前项目的 RAG 不是直接检索订单正文，而是检索数据库的说明书。`meta` 保存表、字段和指标，`dw` 保存业务事实。

对应面试题包括什么是 RAG、RAG 和微调有什么区别、Embedding 是什么、为什么使用 COSINE、向量数据库保存什么。

回答当前项目时要结合具体内容。Embedding 把“成交金额”和“销售额”映射到相近的向量位置。Qdrant 保存字段和指标向量及其说明。Elasticsearch 用于查找“华东”这类具体值。检索结果只是依据，最终 SQL 仍需校验。

学习动作是打开 `conf/meta_config.yaml`，选择 `fact_order`、`dim_product` 和 `dim_region` 三张表，分别找出事实表、维度表、主键、外键、指标字段和别名。然后查看 `app/services/meta_knowledge_service.py`，理解配置如何进入 MySQL、ES 和 Qdrant。

## 五、第三阶段，学会 LangGraph 工作流

当前 Agent 是受约束的工作流型 Agent。节点和路径是代码明确写出的，模型不会自由创建任意工具循环。

对应面试题包括什么是 Agent、LangGraph 的状态节点边、如何扩展第三个工具、为什么不做自主 Agent 循环、什么时候需要 recursion limit。

面试时要主动说清边界。当前图是有限路径，没有工具循环，所以重点是条件路由和节点职责。若以后加入反思或多轮工具调用，再增加循环上限、工具白名单和失败终止条件。

学习动作是逐个阅读 `app/agent/nodes/` 下的节点。每个节点只回答四件事。读取哪些状态，调用什么外部服务，写回哪些状态，失败时怎样处理。

## 六、第四阶段，学会 SQL 生成和安全校验

问数 Agent 的难点不是让模型写出一条看起来像 SQL 的字符串，而是让它只使用真实表和字段，遵循业务指标口径，并且不执行修改数据的语句。

对应面试题包括如何防止模型幻觉、为什么需要上下文过滤、SQL 校验失败后怎么处理、如何限制工具参数和查询范围。

学习动作是准备三条问题。简单聚合、带地区筛选、带时间分组。每次保存原始问题、召回上下文、生成 SQL、校验结果和最终数据。然后故意把字段名改错，观察校正节点怎样工作。

## 七、第五阶段，学会异步和工程化

对应面试题包括 `async def` 的作用、同步 SDK 为什么会阻塞、为什么要用连接池、生命周期和依赖注入分别负责什么、Pydantic 做什么。

当前项目中 MySQL、ES、Qdrant 和 Embedding 都是外部 I/O。异步接口可以在等待网络时处理其他请求，但异步函数本身不会自动把同步 SDK 变成异步。代码中使用的客户端管理器负责初始化和关闭资源，FastAPI lifespan 负责应用生命周期。

学习动作是打开 `app/core/lifespan.py`、`app/clients` 和 `app/api/dependencies.py`。分别画出启动、请求、关闭三条路径。

## 八、第六阶段，建立自己的评测集

评测文件已经放在 `evals/questions.json`，包含七条基础问题，覆盖聚合、筛选排序、分组、时间分析、未知指标和闲聊。

每条问题至少记录用户问题、期望类型、标准 SQL 或标准结果、生成 SQL、是否执行成功、结果是否正确、错误节点和耗时。

建议先手工跑通七条，再写一个批量脚本调用 `/api/query`。第一版只统计接口成功率和结果正确率。第二版再统计关键词召回率、SQL 执行率、平均耗时和 Token 消耗。

## 九、面试高频问题与当前项目答案

问为什么不用一个大模型直接回答。因为模型没有可靠的数据库结构和业务口径，直接回答容易猜字段和编造数字。当前项目先检索元数据，再生成 SQL，并在执行前校验。

问为什么同时使用 Elasticsearch 和 Qdrant。Elasticsearch 适合查找具体业务值，Qdrant 适合查找语义相近的字段和指标，两者承担的召回任务不同。

问为什么章节查询的面试案例不能直接套到当前项目。章节号是小说项目的结构化过滤条件，当前项目对应的是地区、商品、客户和时间字段。可以迁移“结构化条件优先使用精确查询”的原则，不能虚构当前项目存在章节工具。

问如果召回为空怎么办。当前流程应返回可解释的失败状态，不能让模型脱离上下文编造表和字段。还可以增加相似度阈值、查询改写和混合检索。

问如何扩展一个新工具。增加工具函数、状态字段、节点和条件边，再增加一组分支测试。工具参数必须做白名单和类型校验。

问怎么证明项目有效。用固定评测集跑回放，比较标准结果和 Agent 结果，同时保存 SQL、日志、耗时和错误节点，不能只展示一次成功截图。

## 十、四周学习安排

第一周只学数据层和 RAG。完成表结构、元数据、Embedding、ES 和 Qdrant 的手绘链路。

第二周只学 Agent 图。逐个节点阅读代码，自己修改一个提示词，观察 SQL 变化。

第三周只学 FastAPI 和工程化。理解依赖注入、生命周期、中间件、SSE、日志和异常处理。

第四周做面试演练。每天随机抽三道面试题，用当前项目举例回答；每晚跑一遍七条评测问题，记录当天修复的一个问题。

## 十一、最终验收

你可以独立启动前端和后端，完成一次真实问数。你能画出从用户问题到 SQL 结果的调用链。你能解释 MySQL、ES、Qdrant、Qwen Embedding 和 DeepSeek 各自负责什么。你能指出 Agent 的边界，知道哪些地方是规则，哪些地方是模型。你能用评测集判断一次改动到底让系统变好还是变坏。
